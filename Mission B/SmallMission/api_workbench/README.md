# Mission B 3.0.7 — API 辅助链接核验

独立运行的师资名单 URL 核验工具。支持粘贴文本、CSV、XLSX/XLS，以及“个人url＋师资url”双表格式。输入可包含多个学院，工作台显示缺少、多出和无法判定的原因，并提供四列核验汇总表、分学院修正表、逐条来源证据。

只需要导入和下载的使用者可使用独立的[精简分发版](README_lite.md)。下文仍为本地完整版说明。

本文件描述当前完整版源码。历史版本、实跑记录和本地证据的位置见 [档案索引](../../docs/README.md)；已发布包保留原样，不能用当前源码版本代替旧包版本。

## 输入格式

四列表包含 `学校、学院、师资URL、教师URL`。双表将师资入口与教师链接分开，两张表通常分别包含 `学校、学院、师资URL` 和 `学校、学院、教师个人URL`，按学校和学院关联，不按行号配对。

单学院工作簿也支持第一张表为 `ID、学校、学院、师资URL`，另一张表为 `姓名、个人URL`；ID、姓名不参与 URL 比较。只有师资表对应唯一的学校和学院时，教师表才可省略学校、学院，两张表的顺序不限。多个学院时须在教师表写明学校、学院。教师表可只有表头，重复链接与无主页占位沿用现有规则。

## 启动

源码运行：在本目录使用已安装 `requirements.txt` 依赖及 Playwright Chromium 的 Python 执行 `python app.py`。Mac/Linux 也可使用本目录的 `run.sh`。当前源码包含静态页面零链接时尝试浏览器渲染的修复；渲染仍无法取得有效名单时继续保留特殊情况。

使用已有完整版发行包时，按包内说明启动；[发行说明](README_distribution.md) 对应 3.0.1，不包含后续源码修复：

- Windows 64位：完整解压后双击 `MissionB.exe`，无需另装 Python。保留 `_internal` 和 `.browsers`。
- macOS：双击 `install-macos.command`，以后用 `start-macos.command`；也可在该文件夹运行 `bash run.sh`。
- Linux：运行 `bash install-linux.sh`，以后运行 `bash run.sh`。
- Mac/Linux 首次安装会下载独立 Python、依赖和 Chromium。Linux 系统组件缺失时会询问是否安装，可能需要管理员密码。环境保存在工具文件夹，安装日志在 `.runtime`。Mac/Linux 安装逻辑已有自动测试，未完成实机验收。

进入“API设置”，填写自己的 DeepSeek 密钥并应用，再导入或粘贴数据。密钥只保存在当前程序内存，退出后需重填；命令行运行也可通过 `DEEPSEEK_API_KEY` 环境变量提供。发行包不包含作者密钥、任务或缓存。

默认调用官方 `https://api.deepseek.com` 的 `deepseek-flash`。每个新页面通常两次结构判断，受每批调用上限限制。网页正文会发送给 DeepSeek；原始上传表及其数量不发送。工作台显示调用次数和 tokens，实际费用以服务商账单为准。

也可选择“已有区域规则”，不调用 API，只适用于已有配置的来源。工作台仅监听本机。关闭网页不停止后台；请用左下角“退出工具”。

## 核验口径

范围为提供的师资入口及同栏目分页，不自动扩展其他栏目，不访问教师目标页。不核实身份、在职状态、职称、邮箱或全院完整性。

名单条目真实存在的 HTTP(S) 链接按源保留，包括条目指向学院首页、英文姓名、同名不同 URL、集体介绍。仅按结构排除导航、面包屑、分页、页脚和相关推荐。无链接的纯文字不编造网址。

名单资格也允许正文列表中的院系、团队或导师集体介绍文章，不要求条目先出现个人姓名；单条或附发布日期不构成排除理由。仍须依据正文标题、条目列表及上下文区分实际师资介绍与独立栏目目录。文章布局、日期或“师资队伍”标题本身不能证明资格；培训、获奖等混合主题无法明确分出名单范围时继续特殊情况。

重复 URL 按一条比较。仅协议 http/https 不同，其余部分相同，不单独判错；保留路径、参数和片段差异。最终比较 URL 集合，数量相等但地址不同仍属于差异。

四列汇总为 `大学名 学院名 核验结果 特殊情况说明`：

- `正确`：全部指定来源和可识别分页完成核验，链接集合符合现有规则。
- `错误`：已确认原表缺少或多出链接，即使自动修正后仍为错误。
- `特殊情况`：无法可靠判定，需要人工处理。网页无法访问、分页不完整、名单不明确、模型判断不一致等均使用此分类，已知原因放入“特殊情况说明”。

说明允许为空，原因不明也不能判为正确或错误。同学院有多个独立核验分组时，已有分组确认差异则汇总为错误，其他分组未完成的原因仍保留在说明列。界面、四列汇总下载及详细工作簿中的“核验汇总”使用同一分类。详细日志、差异和证据保留；历史文件不改写，历史下载标明旧格式。

网页失败或不确定不会当成零链接，不会据此清空原表。生成的新表不覆盖上传原件。结果基于核验当时页面，不能反推历史网站的状态。

## 怎样限制错误

模型只选择实际网页节点编号，程序从原件枚举网址。两次独立提示的选择必须一致，检查全部实际锚点而非只比较总数；页码有声明时检查覆盖。整页误选、零链接、脚本目标不明和分歧都保留待核。

名单选择被外层排除区域覆盖，或两次选择的锚点不一致时，保留初次证据，并在本批额度允许时增加一次独立复核，每路只收到自己的原选择与结构反馈。复核最多增加两次 API 调用；额度不足、复核后仍冲突或范围不明时保持特殊情况。实际侧栏名单可纳入；只有其他名册入口的目录页、通用新闻轮播不能直接当作名单。

即使两次选择一致，程序也检查已选链接向上的同容器平行结构：相同标签、class 和子树形状的兄弟条目存在未覆盖的不同 URL 时，记录具体节点并触发上述独立复核，不自动补入较大集合。明确排除的区域与同 URL 重复卡片沿用原规则。此检查只覆盖可比的重复结构，不能证明所有名单区域均已发现。

名单中的 `javascript:;`、`javascript:void(0)`、`javascript:void(0);` 仅在没有内联事件时视为确切空操作，不阻断同名单已取得的 HTTP(S) 链接，也不为无主页条目生成地址。未知脚本或带内联事件的占位链接继续人工核准。

所选链接或其祖先带 `hidden`／`aria-hidden="true"` 标记时，可点击范围保留人工核准，不直接增删原表链接。这是已知隐藏标记的检查，不是完整的 CSS 可见性判定；链接内装饰图标的隐藏标记不影响链接本身。

API 模式读取分页区域中的页码，包括“第 [1] 页，共 [1] 页”。仅在当前页和总页数唯一一致时，排除同路径 `page` 参数大于总页数的目标，避免网站末页的无效“后一页”不断生成空页面。其他分页地址继续沿用原规则，实际缺页仍须人工处理。

支持日志中出现的 `Index_2.html`、`Index_2.aspx`、`index1.htm`、`index_2.shtml` 和 `shizi_2`／`szdw_2` 同栏目分页。明确禁用的按钮不作为下一页；空 href 上固定的 `location.href=encodeURI('地址')` 可作为分页目标，只解析字面地址，不执行脚本。跨栏目、未知脚本、缺页和访问失败继续保留特殊情况。

同栏目组件分页须由实际 `.p_pages` 控件、唯一当前页及一致页码佐证；只有主机、路径、片段、栏目固定参数、组件及每页数量均匹配时，才接纳观测到的 `a数字t/p/c` 参数分页目标。保留其他查询参数，逐页核对覆盖；更换栏目或组件、总页数矛盾、缺页和访问失败仍保持特殊情况。

3.0.6 增加实际控件支持的 `lists_栏目ID_N.html`、固定 `C数字index_N.htm` 和 `PAGENUM` 附固定 `totalpage` 分页，以及 `.this-page` 当前页组件。必须有唯一当前页和一致总页数、真实数字链接及完整页码范围或末页证据；只读取实际出现的地址，保留栏目 ID、前缀、扩展名、其他固定参数和片段边界。PC／移动控件页数矛盾仍需人工处理。

标准附加输入跳转仅在同一分页区域内输入 ID 唯一、标准处理器及总页数一致、没有其他事件时不再阻断已完整读取的 HTTP 分页；程序不执行脚本或生成地址。单页终止要求独立 DOM 明确声明当前 1／总共 1，不能只依赖处理器参数为 1。未知 Next、未知脚本、额外事件、缺页、失败或矛盾继续特殊情况；Next／尾页即使带 HTTP 地址，有未知事件仍需人工核准。冻结回放不证明新模型选择或学院完整性。实施与后续验收查 [Issue #50](https://github.com/normaltank/NewPlan/issues/50) 和本地 `maintenance/20261102-log-maintenance/README.md`。

3.0.7 支持在真实浏览器中逐页观察有限客户端预载分页。当前仅支持带唯一 ID 的同父级隐藏预载／可见容器、带公共 class 的直接条目及单一 `.pb_sys_common` 的原生 `data-page` 控件。两路名单选择均须覆盖完整预载条目；程序逐页核对可见条目的文字和实际 URL，要求各页合并后的条目多重集与预载完全相同、URL 集合与两路选择一致，并验证连续页码以及末页“下页／尾页”控件均已禁用。隐藏预载或数量相同本身不能证明完成。

桌面客户端观察默认上限为 30 页／45 秒，服务器配置见[下节](#服务器有限配置)。不生成脚本地址、不访问教师目标；额外 document／XHR／fetch 请求在发出前拦截。逐页 HTML、摘要与拦截记录保存在来源证据的 `client-pagination.json` 及 `client-page-*.html`。仅解除被证明结束的该分页待核；每次浏览器快照同时检查其他独立未决下页／尾页，首次渲染或点击后新增的控件继续待核；未知脚本、空目标或额外内联事件即使没有分页包装也保留待核，已识别独立分页容器中的 HTTP 目标同样不由当前控件证明。未知脚本、额外内联事件、模型分歧、条目遗漏或替换、内容变化、循环、矛盾、超限、停止及其他未决原因继续保留特殊情况。回放旧静态页不复用本次浏览器观察结论。集体师资文章仍按上方[核验口径](#核验口径)判断资格；本轮分票实施与后续整体验收查 [Issue #56](https://github.com/normaltank/NewPlan/issues/56) 和本地 `maintenance/20261103-special-repair/`。

每次运行重新取得网页。只有清理后的完整页面、来源 URL、模型、有效运行上限和判断代码版本完全相同，才复用不超过7天的合格缓存，并重新验证节点。内容、配置或判断版本变化会重新调用。

这能降低误判，但同一模型两次一致仍可能共同漏选区域，不能据此承诺任意高校100%准确。新网站建议首次抽查“逐条证据”中的未计入链接及完整分页。隐藏脚本、复杂交互、图像内没有实际超链接的名单、访问限制等可能需要人工。

`data` 保存任务、输入、HTML原件、每条计入/未计入记录、模型回答、用量和摘要。转发软件请用干净发行包，不要把个人 `data` 一并发送。

## 服务器有限配置

调用方可给 `audit.run(args)` 的 `args.limits` 传入 `run_limits.RunLimits()`、JSON 文件路径或局部配置对象；局部配置用服务器默认值补齐，未知键、零、负数、非整数均拒绝。`parse_file`、`read_directory` 的可选 `limits` 参数使用相同配置。不传配置时保持桌面入口及其上传限制；服务器调用不经过桌面 UI。服务器输出可指定为代码目录外的新目录，缓存通过 `args.cache_dir` 外置，已有输出目录仍拒绝覆盖。

服务器默认每批 200 文件、250000 数据行、每文件 64 MiB、XLSX 解压合计 256 MiB、每工作表矩形范围 4000000 单元格、每工作簿合并区域累计展开 500000 单元格、每学院 1000 来源 URL、每批 20000 模型调用、每次模型输入 1000000 字符及输出 8192 tokens、每来源客户端观察 1000 页／600 秒。字段名和精确字节值以 [run_limits.py](run_limits.py) 为准；这些值是交接起点，不是实测服务器容量或费用保证。

来源页预算按同一学校／学院合计给定入口和新增分页，不能靠多个输入分组绕过；仅以协议不同的同一来源按一个预算地址计数，仍保留原 URL 逐项对账。客户端观察页数单独作用于一个来源的实际连续页。模型输入字符数包括发送的 system 文本和完整 user JSON（复核反馈也计入）；每次初判或复核均需保留两路调用额度，剩下一次额度时不启动单路。网络请求、循环、同栏目边界、未知 Next／片段事件、取消及真实末页证据检查继续生效。

文件大小和批文件数在读取、哈希及复制内容前检查；工作簿解压大小、单元格范围和累计合并展开先检查，再解析。超文件／行／展开预算整文件拒绝，累计行数只接纳完整文件，后面的可容纳文件继续处理。未解析文件以 `record_type=input_file`、`input_file=原文件名` 留下特殊情况，学校／学院留空，文件名与原因进入四列汇总的说明。未读取文件不保存内容副本和哈希（`sha256=null`、`unread=true`），须保留原件；其他已读取原件保存在本次输出的 `inputs/`。

学院触顶时保留原表和已经取得的证据，该学院全部分组归特殊情况，不用部分名单出具完整修正表；其余学院继续。`manifest.json` 的 `limits`、`limit_profile`、`input_rejections`、`limit_events` 与 `limits.json` 保存有效配置和未处理范围。运行代码快照包含配置模块，模型缓存契约也包含有效配置。完成含特殊情况的批次仍会生成报告；测试、模型一致或运行完成不证明全院完整性。实施证据见本地 `maintenance/20261103-server-handoff/ticket62/`，需求见 [Issue #62](https://github.com/normaltank/NewPlan/issues/62)。
