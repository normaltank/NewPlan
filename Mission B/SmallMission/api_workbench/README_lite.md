# Mission B 精简分发版 1.0.5 · 维护说明

使用者只需 **选择文件 → 开始核验 → 查看结果**，下载核验结果和错误学院的更新链接。使用现有 3.0.2 核验引擎，包含静态零链接时的浏览器渲染修复；分页、去重和逐链接比较规则不变。本地完整版及历史数据独立保留。

## 分发

将 `release/MissionB-Lite-Windows-x64-v1.0.5.zip` 完整解压到较短的可写路径，例如 `D:\MissionB`，双击 `名单核验.exe`。过长的解压路径可能导致内置浏览器无法启动。Windows 64 位包自带 Python 与浏览器，包含所有者授权的分发密钥及日志发信配置。使用者无需输入密钥或邮箱，也看不到 API 设置、用量、历史列表或详细证据。必要的运行状态、停止与退出仍保留。关闭网页不退出后台。

进度条显示实际完成项数与百分比，刷新后恢复；每个核验分组完成后更新，不估算剩余时间。单个分组处理期间数值可能保持不变。整理阶段显示等待状态，结果和日志整理完成才显示 100%；没有错误也正常完成。停止或失败后不保留完成进度。

每批最多选择 20 个文件，页面明确提示，前端和服务端均拒绝超限提交。单文件 10MB、文件合计 20MB 的限制保留。支持可折叠的粘贴输入；文本、CSV、TSV、XLSX、XLS 与原有双表规则保持一致。输入模板可直接下载。最近一次结果可在刷新或重新打开后恢复。

每次开始核验会提交当前选中的文件和粘贴框内的全部内容。重新选择文件替换上次选择，不自动带入历史任务；完成后仍选中的旧文件、仍留在粘贴框中的旧文本会再次提交，折叠粘贴框不会清空文本。运行期间不能排入下一批。输入提交实现见 [lite_web/app.js](lite_web/app.js)。

分发给使用者的说明仅列操作步骤与日志位置。本文件属于维护文档，不放入 Windows 用户包。请使用干净发行包分发，不复制已经运行的文件夹。

## 结果边界

页面直接展示 **学校、学院、核验结果** 三列，结果沿用 **正确／错误／特殊情况**，特殊原因保留在日志，页面只提示人工查看原网页。空说明也按原规则保留特殊情况。

下载 ZIP 同时包含 `核验结果.xlsx` 和 `核验后链接/` 文件夹。结果表与页面一致，为 **学校、学院、核验结果** 三列，包含本批全部学院；链接文件夹仅放汇总为“错误”的学院更新表，表头为 **学校、学院、师资url、教师url**。不附带使用说明.txt。没有错误时仍可下载结果表，链接文件夹为空。实现见 [lite_app.py](lite_app.py) 和 [页面展示](lite_web/app.js)。

同学院有多个独立分组时，按原学院合并规则筛选，下载保留该错误学院已完成分组的表；未完成分组仍不生成修正表，不能将这些表视为全院采齐证明。旧版 ZIP 保持原样；查看旧任务并下载时另生成新版筛选包，不覆盖旧结果或任务记录。

精简版只隐藏原因，不改变判定。缺少原因仍不能判为正确或错误；数量相等而 URL 不同仍判错。已有独立分组确认差异时的学院合并规则保持不变。未完成分组不生成空修正表、不清空原始链接。下载不包含详细对账、证据或模型记录。输入原件不改写。

## 日志与复现

预配置邮件在任务完成且学院汇总至少有一项“特殊情况”时，后台发送本批日志。纯“正确／错误”任务、取消、运行失败和历史任务不自动发送。说明为空不影响触发；学院合并后仍为“错误”的分组不单独触发。页面底部简短告知自动回传，不增加操作步骤。任务结果下载不等待发信。

附件为仅含本批 `MissionB.log` 的 ZIP，包含对应启动信息、输入、网页和模型证据，可用下方工具还原。不会整份上传累积的历史日志。发件和收件地址固定在维护配置，不允许网页改写。邮件传输使用验证证书的加密 SMTP。

发送记录位于 `lite-data/mail-outbox/<任务ID>`。明确失败后保留压缩日志，下次启动重试，最多尝试三次；成功后不重复发送。邮件提交后连接中断或程序中途退出时，若是否接受无法确认，记为 `uncertain`，不自动重发，维护人员结合邮箱与任务 ID 判断。SMTP 接受表示交给发件服务器，不等于收件箱已收到。超过 18MB 的压缩日志保留本地，需人工传回，不截断证据。本地 `MissionB.log` 始终保留。

软件根目录自动创建并追加 `MissionB.log`，用户遇到问题发回此文件即可。包含版本、代码指纹、解析后的输入、来源 URL、配置、结果、失败堆栈，以及已取得的网页和模型请求／响应证据。日志过滤实际运行密钥、会话令牌和授权字段，不记录授权请求头。证据采用压缩编码，仍在同一个日志文件内。

本地运行数据单独放在 `lite-data`，不读取或改写完整版的 `data`。未取得的网页、突然退出前未写入的证据、变化后的外部服务，不能靠日志保证重现。原始 Excel 文件另在本地保留，日志包含解析后的行和来源定位。

维护环境执行 `python read_lite_log.py MissionB.log 新建证据目录`，默认还原最后一批；`--job-id` 指定任务。该工具只读取日志，不联网、不调用模型。`run.json` 包含输入与环境，`evidence` 保留网页、模型和结果材料。需要排查输入文件本身时，再向使用者索取原件。

## 配置与构建

开发时运行 `python lite_app.py`，使用 `DEEPSEEK_API_KEY` 或未入库的 `lite_config.json`。Windows 发行包从 `_internal/lite_config.json` 读取预配置密钥，只在服务端使用，不通过网页或状态接口返回。网页不能修改密钥或切换引擎。

邮件配置从未入库的 `mail_config.json` 读取，字段为 `host`、`port`、`sender`、`recipient`、`password`，端口默认 465；未提供时关闭自动回传。维护凭据使用 Windows 当前用户加密的 `mail-authorization.dpapi`。构建时添加 `--mail-key-dpapi`、`--mail-sender`、`--mail-recipient` 参数，必要时指定 `--mail-host` 和 `--mail-port`。源码包没有任何发信配置，普通源码测试不会发送真实邮件。

Windows 本地分发包按所有者授权内置客户端授权码；客户端内置凭据仍可能被提取，适合所有者指定的专用发信账号。带发信配置或 API 密钥的包不得上传公开仓库。构建阶段目录同样含配置，属于本地维护资料。

分发密钥的维护副本通过 Windows 当前用户加密，保存在 `%LOCALAPPDATA%/MissionB-Maintenance/distribution-key.dpapi`，不写进代码或文档。构建使用独立环境：

```powershell
.lite-build-env/Scripts/python.exe build_lite.py --key-dpapi "$env:LOCALAPPDATA/MissionB-Maintenance/distribution-key.dpapi"
```

构建仅复制白名单文件，浏览器从 3.0.1 正式包核验哈希后复用，不携带本地任务或缓存。Windows 包按本次授权携带分发密钥；维护源码 ZIP 不携带密钥，需要维护人员自行配置。源码 ZIP 不包含跨平台自动安装器，未做 Mac/Linux 实机验收。
