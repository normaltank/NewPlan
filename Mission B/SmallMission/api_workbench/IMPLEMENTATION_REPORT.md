# Mission B 3.0：方案与验收记录

日期：2026-10-15。此版本在 `SmallMission/api_workbench` 独立实现，基于已发行2.3.0。没有接入主采集数据库，没有替换主工作台，也没有改动旧包或用户输入文件。工作目录中先前暂停的“只比较数量”改动没有带入。

## 采用的方案

主工作流的 API 客户端被复用于调用额度、用量记录、结构化返回和凭据脱敏；“模型提出结构方案、程序执行”的方式缩小为选择真实网页节点编号。独立 Mission B 的输入、网页获取、分页队列、对账、导出和界面继续复用。

没有把主工作流的姓名过滤、教师身份合并、邮箱职称提取带入本任务。这些能力会改变“名单条目中的实际URL”口径。

API 只找区域，不生成网址或计算交付数量。完整清理页面分别做两次结构判断，第二次看不到第一次答案，也看不到原表。程序校验节点，枚举原件中的链接，要求实际锚点及分页集合一致；分别记录所有计入和未计入链接。

分页有页码时检查覆盖；缺页、模型分歧、整页误选、零链接和脚本目标不明都保留待核。新增了“脚本下一页不能当成已结束”的检查。访问失败不判为原表错误，不会据此清空原表。

每次重新取得网页；仅来源、清理后全文、模型及判断代码版本完全相同，才复用7天内的合格答案，并重新验证节点。网页变化会重新调用。缓存存的是区域选择，网址和数量仍来自本次网页。

已提供独立界面中的 API 设置、每批调用上限、调用次数和 tokens、逐项来源证据、混合文本/文件输入，以及原有三列汇总和分学院修正表。密钥只保存在进程内，发行包不包含密钥和任务数据。

## 能作出的结论

API版能减少未知名单结构逐校手写选择器的工作，但现有证据不能证明其准确率高于正确配置的规则版，也不能保证任意高校100%准确。两次同一模型一致仍可能共同漏选区域。

目前有独立逐URL依据的范围是上述保存页和两个新网页。对新学校的首次结果，仍建议抽查未计入链接、全部并列分组和分页，积累带原件的回归案例。网站不可访问、复杂交互未解析或输入范围不全，不能用API置信度替代证据。

不继续堆叠学校名条件：通用机制放在网页获取、真实节点、分页和对账层；确需特例时用独立配置与带原件的回归样本约束。后续模型或提示词升级，也应重跑这些样本，再看未参与调试的新页面。
