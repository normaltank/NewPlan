    CONNECTION & LIMITS

    API 设置

    让 DeepSeek 识别名单范围，程序从原网页逐条读取链接。

    密钥仅保存在本次程序内存中，不写入任务、缓存或导出文件。关闭程序后需重新填写；也支持由运行环境提供密钥。

    每个新页面通常需要两次判断；相同网页的有效缓存无需重复调用。达到上限后保留原表并标为未完成。

    固定使用 DeepSeek 官方接口和 deepseek-flash。模型不会看到原表数量；不能生成网页中不存在的网址。判断分歧、缺页和零链接不会自动判为通过。

    A SMALL, FOCUSED TOOL

    使用说明

    回答一个问题：通过这个师资页获得教师主页链接，还需不需要人工介入？

    三步完成

    1. 上传“个人url＋师资url”双表 Excel，或粘贴／上传原有四列格式。双表的两张表按学校、学院名称对应，不按行号配对；可上传多个学院的文件。
    2. 查看预览，修正行号提示的格式问题，再开始核验。
    3. 下载四列“核验汇总”：大学名、学院名、核验结果、特殊情况说明，每个学院一行。需要追溯时另下载详细核验表。

    汇总表怎么看？

    正确：全部指定来源及其分页完成核验，链接集合符合现有规则。错误：已确认原表缺少或多出链接，自动修正后仍为错误。重复本身及仅 http/https 写法不同不单独判错。特殊情况：无法可靠判定，交给人工处理。网页无法访问、分页不完整、名单不明确、模型判断不一致等均归入特殊情况；已知原因放在说明列，说明允许为空。原因不明也不能判为正确或错误。

    同一学院有多个独立核验分组时，已有分组确认差异则汇总为错误，其他分组未完成的原因仍保留在说明列。详细日志、逐项差异和来源证据继续保留。历史下载保留原有格式。

    详细结论怎么看？

    详细记录中的“原表吻合”“已自动修正”和“需人工介入”说明处理过程，不替代汇总分类。特殊情况不会当成零链接，不自动增删原表。

    本版适用范围

    API模式支持识别未配置的名单页面；结构不明时保留待核。已有规则模式只处理已配置页面。

    输入格式兼容不等于网站结构通用。API模式会对完整页面做两次结构判断，并验证真实链接及分页；分歧留待人工。相同内容和判断版本的合格缓存最多复用7天，读取网页仍每次进行。

    计数与边界

    • 统计的是链接，不是人数。同一URL展示多次只保留一条；同名不同URL不会按名字合并。
    • 给定师资页及同栏目的分页合并去重后对账，跨页重复不会重复计入。未读取全部来源时不自动删除原表链接；不自行扩展到未提供的栏目。
    • 空链接、#占位和没有可见内容的空锚点单独记证据。已给出HTTP地址但疑似指向首页的姓名链接按源保留并提示。
    • HTTP/HTTPS差异显式记录为“按源修正协议”，不推断目标页面等价。
    • 核验基于本次取得的页面。不能据此推断历史采集当时的准确度，也不验证邮箱、职称、教师身份或全院完整性。

    运行与保存

    API模式需要自己的 DeepSeek 密钥并按用量付费；已有规则模式无需 API。抓取学校网站仍需要网络；页面响应慢或限制访问时可能无法完成。工作台只监听本机，关闭浏览器标签不会结束任务；通过左下角“退出工具”关闭后台。

    数据与结果在工具文件夹的 data 子目录，原始输入不会被覆盖。发给其他人时使用干净的发行压缩包；不要把自己的 data 文件夹一起发出。

    macOS/Linux 自动安装版首次运行会联网安装独立 Python 环境、依赖与 Chromium。浏览器组件无法安装时，请按压缩包内说明处理。
