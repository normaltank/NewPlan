# Mission B：DeepSeek 辅助结构识别试验

本目录是独立试验，未替换 Windows 安装包或主工作台。问题是：能否借用现有主工作流的模型结构识别方式，减少逐个学院手写名单区域配置，同时正确执行 Mission B 的 URL 统计口径？

先看 [试验结论](REPORT.md) 或 [可视化报告](overview.html)。

## 实际复用与边界

- `vendor/deepseek_api.py` 是主工作流 JSON 客户端的固定副本，复用调用上限、用量记录、凭据脱敏、非正常结束检查；来源和摘要见 `provenance.json`。
- `vendor/audit.py`、`input_adapter.py`、`runtime_paths.py` 固定于已发行 Mission B 2.3.0，复用 HTTP/浏览器获取、分页范围及 URL 规范化能力。
- 主工作流的“模型生成结构方案 → 程序执行”做法被缩小为选择真实网页节点编号；不导入人员姓名过滤、身份合并、职称邮箱或简介采集。
- 不读取主数据库、不更改主服务；没有将工作目录里暂停的数量判定改动带入试验，也没有回滚它们。
- 仅对给定师资入口和同栏目的分页核验。目标个人页不访问。条目指向首页仍保留；同名不同 URL 保留；不因标题不像姓名而剔除条目。

## 本轮执行

1. 将保存网页完整清理后，为真实元素赋予编号；没有静默截断。输入原表、旧版区域规则和旧计数不提供给模型。
2. 模型分别作两次结构判断。第二次看不到第一次的答案。每次选择名单区域、分页区域和有依据的非正文区域。
3. 程序校验编号存在，从原件枚举 URL，单独排除分页锚点。只排除该节点，不能按目标 URL 全局删除，否则会误删合法的首页链接。
4. 两次区域判断的实际锚点和分页集合必须一致；从给定入口验证分页可达性。失败或分歧保留待核，不清空原表。
5. 原表逐 URL 集合比较，http/https 单纯协议差异按既有口径处理。两次模型同意不是独立真值，报告明确保留这一限制。

第一轮为20学院、62份保存网页。第二轮仅对延安、湖南、沈阳3学院、6页实时复查。没有重试已知受限的陕西理工网站。

## 重新运行

现有项目环境（PowerShell，在 `OpenSource` 目录）：

```powershell
& .\secure-api-run.ps1 -PythonArgs @('-B', 'Mission B/SmallMission/experimental_deepseek/experiment.py', '--output', 'Mission B/SmallMission/experimental_deepseek/runs/new-snapshot', '--max-calls', '110')
```

独立环境需要 Python 3.11+ 及 SmallMission `requirements.txt` 中依赖，由运行者设置自己的 `DEEPSEEK_API_KEY`；不复制作者凭据。然后执行：

```text
python -B experiment.py --baseline <包含results.json及原件的v2.3运行目录> --output <本试验目录下的新输出目录>
```

`--live --schools 延安大学,湖南大学,沈阳航空航天大学 --max-calls 24` 可进行同一组实时复查。所有输出路径必须是本试验目录内全新的子目录。当前版本是对已有基准运行的实验程序，尚不是面向任意上传表格的发行版功能。

## 后续采用方式

本轮采用逐页双调用，以观察是否一致；未实现跨运行结构缓存、自动修正规则或正式版 API 设置界面。建议正式方案保留已验证规则，陌生或变化的结构才调用模型，并保留分页与范围检查。上线前还应使用未参与调试的新学院验证，而不能把本次20学院当作泛化证明。
