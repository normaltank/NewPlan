# Domain Docs

本项目采用单一上下文，沿用 [CONTEXT.md](../../CONTEXT.md) 的业务与交付契约，以及 [文档导航](../README.md) 中的职责划分，不复制第二套需求。

## 阅读规则

开始探索时先读 CONTEXT 和 [GLOSSARY](../../GLOSSARY.md)。若 `docs/adr/` 存在，阅读与修改范围相关的决策记录。

修改术语或记录决策前读 `domain-modeling`。术语只保存已明确的业务定义；决策同时具备难以逆转、缺少背景会令人费解、存在真实取舍三个条件时才建立 ADR。没有合适决策时不创建空目录。

## 布局与维护

- 术语表：根目录 `GLOSSARY.md`。
- 决策记录：`docs/adr/NNNN-简短主题.md`。
- 项目当前不使用多上下文 `GLOSSARY-MAP.md` 布局；Mission B 的独立使用说明继续按现有目录维护。

问题标题、代码设计、测试和文档使用已定义术语。发现术语缺口时先核对 CONTEXT 与实际实现；变更如果与已有 ADR 冲突，明确指出冲突、依据和拟替代决策，不能静默覆盖。业务要求的权威来源仍为 CONTEXT，具体故障证据留在对应维护目录。
