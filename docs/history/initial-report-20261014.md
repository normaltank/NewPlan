# 开源组件调研与首轮获取试验

日期：2026-10-14，Asia/Singapore。用户已明确：优先评估如何取得数据；上一条、下一条和公共联系方式混入正文可以后续清理。本报告据此把获取、提取、清理和最终验收分开。

## 判断

值得建立开源组件对照。目前取得的证据支持继续试验，但不足以断言换框架就能解决整院采集。项目已经在 [CONTEXT.md](../../../CONTEXT.md) 确认原件、分阶段处理、可复用能力及局部问题保留等目标；需要比较的是实现这些目标的复杂度与实际获取表现。

首轮已在本目录安装并实际执行三个 Python 开源发行包：Crawl4AI 0.9.4、Crawlee 1.10.4、Trafilatura 2.3.1。使用独立虚拟环境、独立输出，无付费模型调用。项目业务代码、生产队列和服务未改动；没有提交、推送或部署到生产。

## 把需求拆开后，可以参考哪些项目

“本项目可怎么用”是本轮建议，并非声称该工具已经解决我们的业务。

| 小需求 | 项目与官方资料 | 本项目可怎么用 | 首轮状态与边界 |
|---|---|---|---|
| HTTP请求、URL队列、重试、失败保存 | [Crawlee Python](https://crawlee.dev/python/docs/guides/storages)、[失败处理](https://crawlee.dev/python/docs/guides/error-handling) | 把名单分页、个人页获取组织为独立请求，失败保留在具体URL上 | 已实际抓取；本地验证URL去重、一次重试、失败不丢成功结果；崩溃恢复未测 |
| 浏览器渲染、页面交互、规则提取 | [Crawl4AI](https://docs.crawl4ai.com/core/page-interaction/)、[CSS/XPath](https://docs.crawl4ai.com/extraction/no-llm-strategies/) | 按已知结构抓列表；遇脚本生成内容时取得渲染后的DOM | 已测试本机Edge和CSS规则；规则由实验提供，未测试模型生成规则 |
| 从HTML提取较干净的正文 | [Trafilatura](https://github.com/adbar/trafilatura) | 在原始HTML已保存后，生成供阅读和字段抽取使用的正文候选 | 已测试；不会代替名单解析；正文清理效果是次要指标 |
| 从原文提取人名、职称、任职关系并定位证据 | [Google LangExtract](https://github.com/google/langextract) | 输入已保存的个人正文，让字段附带原文片段及位置，再核验 | 下一批优先；需要选定模型；有原文位置仍不自动证明该字段属于目标教师 |
| 页面用途、文本段落等分类 | [SetFit](https://github.com/huggingface/setfit) | 用人工标注样本区分师资名单、个人简介、新闻、组织成员等，辅助路由 | 尚未部署；支持多语种模型，但中文高校网页效果需本地验证；不能套用官方其他任务的样本量或准确率 |
| 把已有启发式变成训练标签 | [Snorkel](https://github.com/snorkel-team/snorkel) | 将标题、链接形态、人员卡片等规则转为可冲突、可弃权的弱标签 | 方法参考；弱标签不是人工真值，Windows官方建议Docker/WSL，暂不优先安装 |
| 标注参考答案、修正分类和原文范围 | [Label Studio](https://github.com/HumanSignal/label-studio)、[Argilla](https://github.com/argilla-io/argilla) | 积累“为什么这是名单/简介/非目标人员”的可复用标注；支持后续训练与比较 | 下一批按需要二选一；Label Studio兼顾文本和图片等，Argilla适合文本反馈数据；服务端尚未部署 |
| 中文图片/PDF读取和版面分析 | [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)、[Docling](https://github.com/docling-project/docling) | 取得附件后，对同一组材料比较OCR、阅读顺序、表格和位置 | 尚未部署；原件获取与OCR读取分开计量，模型权重及运行成本需单独记录 |
| 判断多条观察是否为同一人 | [RecordLinkage](https://github.com/J535D165/recordlinkage)、[Splink](https://github.com/moj-analytical-services/splink) | 依据姓名、已核实个人邮箱、主页等生成候选匹配与待复核配对 | 尚未部署；相似度不直接授权合并；Splink更适合有多个有效比较字段的数据，只有姓名时不足 |
| 人工整理与分类查看结果 | [OpenRefine](https://github.com/OpenRefine/OpenRefine) | 员工检查不一致值、分组清理导出数据，并保留可重复的整理步骤 | 尚未部署；适合快速探索原始表，不替代人员身份确认 |
| 输出表结构与字段状态检查 | [Pandera](https://github.com/unionai-oss/pandera) | 把必需列、值域和自定义一致性检查写成可执行规则 | 尚未部署；只能检查明确编码的条件，不能凭空发现未抓到的教师 |

优先顺序建议：先继续跑 Crawlee/Crawl4AI 的获取对照；再加入 LangExtract 比较自然语言字段提取；需要分类路由时先用 Label Studio 或 Argilla 建样本，再比较简单分类基线与 SetFit。媒体读取和身份匹配各用专项样本评估。

## 分类任务应该怎样拆

1. **页面用途**：名单、个人介绍、新闻、组织成员页、附件等；混合页面允许多个标签，无法确认时保留未知。
2. **结构机制**：卡片、表格、姓名链接、图片名单、普通分页、AJAX、展开加载等。结构特征比纯文本分类更关键，可与页面用途组合。
3. **人员与字段语义**：是否明确属于目标学院，某邮箱属于个人还是公共联系信息，职称是当前还是历史。这一层需要原文及关系证据，不能用“这是教师相关页面”的标签代替。

分类器应辅助选择处理器和安排复核。首先测分类错误是否导致漏掉人员，再考虑平均准确率。训练/验证按学院或站点分组，避免同一模板的相邻页面跨集合造成虚高分数。

## 已取得的证据

### 保存页回放

[运行报告](../../runs/20261014-084719-354316-replay/report.md)。使用现有5份个人页原件和1份名单原件，均为已知回归材料。

- Crawl4AI 采用已有名单选择器，输出60条，和该保存页既有60条姓名+链接参考逐项一致。它只验证这一页，**没有证明全院只有60人**。
- Trafilatura 两种模式和 Crawl4AI 原始HTML→Markdown 均保留了所检查的339个较长DOM文本节点。该指标只测既有选区文本保留，未测短节点、视觉内容、完整简介真值或模板污染。
- Crawlee 本地HTTP故障试验：重复URL只请求一次；临时503重试后保存成功；持续503重试耗尽后单列失败。最终2个成功URL、1个失败URL。

### 从60条到73条：需要跟进真实分页

[首次小范围访问](../../runs/20261014-084736-504121-live/report.md)只访问名单第一页和前三个个人页。用户指出官网实际有73人后，检查已保存原件发现明确“下页”链接 `szdw/1.htm`。

扩展试验已经完成：第一页60条、第二页13条，姓名+主页链接去重后73条，与用户对照数一致。两页名单和73个个人页HTML均已保存，73页均找到正文容器，失败0、跳过0；串行且逐请求等待2秒，整批耗时约2分45秒，没有模型调用。分页跟进来自页面链接，不按73硬编码停止。完整运行结果见 [名单及个人页试验](../../runs/20261014-085512-414466-faculty-pilot/report.md)，逐人浏览见 [73条名单索引](../../runs/20261014-085512-414466-faculty-pilot/records.md)；其 `summary.json`、`records.json`、`pages.json` 记录实际获取范围。这里只保存HTML和可提取文本，个人页中的图片和附件没有另行下载。

首次把“60条提取成功”作为局部模块结果成立，但不足以回答用户最关心的“数据是否拿全”。后续获取评价将分页覆盖、名单条目与个人页对应放在首位。

### HTTP与浏览器获取对照

[运行报告及原件](../../runs/20261014-085356-359656-acquisition/report.md)。普通HTTP使用首次已保存运行，浏览器结果是新访问；来源关联保存在 `http-provenance.json`。

| 已知页面 | Crawlee普通HTTP | Crawl4AI浏览器 | 可以得到的结论 |
|---|---|---|---|
| 湖南师大教授名单第一页 | 取得HTML，选区12条 | 取得DOM，选区12条 | 本次普通HTTP足以读取该页选区 |
| 湖南师大教授名单第二页 | 取得HTML，选区10条 | 取得DOM，选区10条 | 两个分页URL都可访问；本轮URL事先给定 |
| 青海师大副教授名单 | 取得原始HTML，人员链接在原件中 | 取得渲染DOM，额外出现教师姓名链接 | 脚本生成内容的读取路径确实不同，适合浏览器或专门解析 |
| 三明学院教授名单 | 取得HTML，选区6条 | 取得DOM，选区6条 | 本次选区数据可由两种方式取得 |

青海样本进一步检查：原始HTML已包含“王忠”等姓名，但不在 BeautifulSoup 的页面文本结果里；渲染后姓名出现在链接文本中。因此应描述为“原始数据存在，浏览器将其渲染为易读DOM”，而非普通HTTP完全没有姓名。浏览器结果也包含重复/隐藏的原始结构，条目计数需选区去重。

湖南两页浏览器SDK返回的状态码是307，同时给出页面DOM并报告成功；原始返回值已保留，未改写为200。这仍不是全院完整性证明。历史失败涉及旧运行和其他阶段，已知URL当前可访问不等于历史整院故障已修复。

### 正文清理现象如何解释

在首次真实访问中，Trafilatura对两个短个人页保留了上下篇导航和学院公共邮箱，对名单页只保留页脚。**完整原始HTML已保存，名单60条也可从HTML提取；这是正文筛选和后处理问题，不记为获取失败。** 原件可用于重新提取，不必重抓。

## 下一步比较什么

建议把已知成功站、已知困难站和未参与适配的新站分别比较，独立记录入口发现、分页到达、名单条目、个人页原件和附件获取情况。工具获得页面后，再统一比较姓名/链接、字段、正文与人工工作量。不要将一个站调好的选择器当成自动发现能力。

上述首轮仍未验证从学院主页自动发现所有师资分支、同URL AJAX翻页、登录/验证码、复杂附件，以及跨站未见材料泛化。官网人数与程序计数一致是有用对照，但人员身份、字段归属及其他未知分支尚未独立验收，**全院完整性未验证**。

## 后续：阜阳师范大学化学与材料工程学院

用户指定新学院后，沿其首页四个师资入口进行了单站试采，结果见 [完整记录](../../runs/20261014-091002-654625-fynu-collection/report.md)。16份名单页覆盖教授团队、硕士生导师、博士团队、教师队伍；三个分页栏目的51、65、18条文章分别与官网总条数及末页对上。文章条数不直接当作人数：其中有博士汇总名单和2016年考核公示。

博士汇总PDF保留113个姓名，统计日期为2025年9月，为HTML姓名条目补充10个姓名。各来源合计279条名单观察、136个不同姓名；134个个人URL中107个取得正文，27个是官网权限提示页。按姓名查阅，98个有对应标题正文，24个只有受限链接，14个只有名单信息。原件、重复来源和缺口均保留，不按同名合并字段。浏览器抽查受限页面也出现相同权限提示；工具将小型提示页判为anti-bot，不作为学校反爬机制的结论。

这次将获取范围扩展到了富文本无链接姓名和文本型PDF，说明附件解析对名单发现有实际增益。agent仍参与入口、选区和PDF链接的确认，未证明跨站自动适配。名单存在历史内容，学院概况的145名教职工也与本次名单口径不同，**全院完整性及当前在职身份未验证**。采集脚本无LLM调用；主批次约5分20秒，不包含agent适配、预采、PDF处理及浏览器抽查时间。

## 后续：接入DeepSeek API

用户授权后接入官方OpenAI兼容接口，模型`deepseek-flash`。`api_pilot.py`以大学、学院、首页为输入，调用API选择已有入口、生成CSS规则、读取富文本/PDF姓名，程序据此抓取；未加载此前的固定学院入口或旧名单来补人。

[首轮API试验](../../runs/20261014-094801-940441-api-pilot/report.md)暴露了模型生成分页选择器时对首页相对路径过度适配的问题：136个姓名仍全部出现，但只取得60份正文，漏掉后续分页中的个人链接。已保留该失败原件和模型输出，调整提示词，并加入页码未到末页时的单次API重规划。5项离线检查覆盖空入口、权限提示、图片无文字、模型姓名证据不符和相对分页链接失败。

[修订后真实试采](../../runs/20261014-095235-009606-api-pilot/report.md)完成153个网页请求，含16份名单页、134个个人链接和2篇名单/公示文章，另下载1份PDF。136个不同姓名中98个有对应正文，共107份正文；24个姓名只有受限链接，14个只有名单信息。模型调用8次，耗时350.34秒，输入21051 token、输出6031 token，费用按当时官方峰时价估算$0.011257，实际以平台账单为准。

此次同站验证包含上一轮已见材料，不证明陌生站点泛化；第二轮未触发自动重规划，重规划分支只做了离线故障案例验证。没有部署服务器常驻进程，也未改变生产采集调用链。密钥在本机加密配置中，原件、API用量、代码快照与事后对照保存在实验目录。
