## 实习生操作

首页右上角“新建采集”支持逐行填写和从 Excel / CSV / Markdown 表格粘贴。必填大学、学院名、学院链接；第四列师资列表链接可留空，多个链接以分号分隔。有无表头均可，每批最多 100 个学院。当前仍限制为 edu.cn / edu 官网，师资链接须与学院链接同域；不符合时逐行提示，不会悄悄丢弃第四列。

“检查输入”只作校验和预览，不启动采集。相同大学、学院及学院主页的重复行合并，保留合并后的师资入口。点击“开始采集”才创建队列任务；同一次提交重试不会重复创建批次。输入的师资链接会传给采集子进程，核验给定入口的同时继续从学院首页发现其他分支；给定入口与首页相同时也会按师资页读取。

```text
大学 学院名 学院链接 师资列表链接
南通大学 医学院 https://yxy.ntu.edu.cn/
南通大学 护理与康复学院 https://ntdxhk.ntu.edu.cn/ https://ntdxhk.ntu.edu.cn/xkjs/list.htm
```

名称含空格时使用 Excel 制表符或带引号 CSV。当前提供粘贴表格，不含 Excel 文件上传。

1. 从总览进入学院专属 `/review/<运行ID>` 链接。状态每3秒刷新；运行中的材料可看，结束后可提交复核。
2. 填写复核人姓名。人员页左侧是队列，中间是修改表单，右侧保留官网链接、原始HTML、正文、原图和PDF。默认只显示异常；可切换自动入库、重复材料或全部条目。同名且本人正文一致的重复条目自动关联，不同材料并列展示对照。
3. 职称和本人邮箱按照原文依据自动选择，支持临床职称、名单行邮箱、个人卡片及 PDF 表格。正常记录自动入库；缺少公开字段本身不会阻塞。只有归属不明、同名材料差异、邮箱格式错误、读取失败、旧名单或低质量 OCR 等异常进入人工队列。人工处理异常时记录依据、检查身份与归属。规则分值用于排序，OCR置信度用于定位问题，都不代表实际正确率。
4. 错人或重复条目用“排除”并写明依据和对应记录；需要补查则保留待办。可以人工新增遗漏人员并单独确认，也可以补充同域入口创建新采集运行。新运行不继承旧人工结论。
5. 处理采集问题，再独立核对入口、分支、分页及每个条目，提交学院结论。所有人员和问题处理完且完成四项对账才能确认完整；“无师资”同样要求官方依据，并且不能存在已确认人员。零结果不会自动变成无师资。
6. 首页可下载当前批次最新运行的 Excel、教师 CSV、师资链接 CSV；学院复核页也可单独下载。教师表严格采用下方十列。JSON 保留接受方式、规则版本、字段依据、空值原因、待核/排除项、学院结论与人工审计历史。未确认完整时仍可交付当前可用记录，完整性状态保存在 Excel 表头批注及独立的“采集说明 CSV”中。

教师表列顺序固定为：**序号、姓名、职称、邮箱、学校、学院、采集人、采集日期、简介、主页**。“采集人”统一为“自动采集”；“采集日期”为实际运行开始日期（Asia/Singapore），不使用下载或复核日期，未开始的任务不填日期。序号从 1 连续排列。简介保留接受记录中的全文；若超过 Excel 单元格长度上限，明确提示改下载 CSV，不静默截断。原件与审计仍保留在工作台。跨学院仅姓名相同不自动合并；有充分本人证据时按下文规则关联。

批次首页的“按大学下载 Excel（ZIP）”按大学分别输出，一个大学一个文件夹、一个教师工作簿，并保留同大学跨学院的有据身份合并。每份工作簿内仍是下面规定的三张表。若某个字段超过 Excel 单元格的 32,767 字符上限，大学交付包会把完整原文保存为同文件夹的 TXT 附件，并在原单元格提供链接和字数说明；“教师完整.csv”同时保留全部原文。先解压整个包后再打开 Excel。学院单独 Excel 下载仍明确提示超长字段改用完整 CSV，不静默截断。

教师 Excel 固定为三张表，顺序为“有邮箱教师”“无邮箱教师”“主页失效教师”。三表互斥且总数等于合并后的交付人数：存在本次已确认访问失败的主页、且没有已确认可用主页时，优先进入第三表；其余按邮箱是否非空分入前两表。没有主页、尚未读取、只发生附件读取失败，不算主页失效；有正常替代主页时按邮箱分表，失效地址仍写入批注。分类依据本次保存的访问结果，不承诺链接永久有效。十列格式不变，序号在三个表之间连续编号，空表也保留表头。

师资链接、采集说明、合并说明与交付标注改为独立 CSV 下载，不再占用教师 Excel 的工作表。Excel 表头批注保留学院完整性说明，每人主页格批注保留来源、失效链接、合并及待核字段说明。师资链接表固定为 **大学、学院名、学院链接、师资链接**，不填第四列的输入同样会产生此表。一个学院多个入口分行列出；依据已确认/自动接受人员的名单来源或本轮明确核实用途的名录页面生成，排除已认定非师资的来源和后续分页，不直接照抄模型候选或未核实的用户输入。未核实入口时保留该学院、师资链接留空，并在“采集说明”解释，空值不表示无师资。

保存使用版本号防止两人覆盖。新人员或对既有决定的修改，会使旧的学院完整性结论失效并保留审计记录。当前复核人是本机填写的署名，不是经登录认证的员工账号。服务器多人部署前需要接入身份认证；当前服务只接受本机Host，不能直接当作对外服务使用。

## 获取能力与限制

- HTTP保存原始页面，API选择已观察到的入口并生成CSS规则；空名单/正文可由独立浏览器渲染。浏览器仅允许同域请求，不绕过登录或访问限制。渲染DOM另存 `rendered.html`，不覆盖原始响应。
- RapidOCR 1.4.4在CPU上读取中文/英文图片，保留原图、SHA256、识别框、置信度和全文。图片每份15 MiB、40百万像素上限。
- 图片 OCR 后再判断文字用途（`image_triage.py`，`image-relevance-v1`）：已取得独立个人简介、图片只有少量场景/标牌文字、无个人字段线索且符合照片纹理条件时，不因背景文字置信度低而要求人工复核；零碎无关文字同样自动处理。密集文字、姓名/职称/邮箱等个人资料线索优先按资料图检查；关键字段有低置信度时仍需核对。没有足够独立简介又无法读出资料的图片保留异常。此规则不是人脸识别，也不能保证识别所有照片或任意图片简历；不会因为图中有人脸就跳过文字。图片检查结果随自动判断保存，人工决定优先，原图和原始 OCR 不删改。
- 采集问题页面直接显示相关原图与判断依据，已自动处理的图片记录显示“图片文字检查（已处理）”，只需抽查；未处理的资料图展开识别文字供核对。原始识别记录中的候选标记保留当时事实，是否需要人工以最新自动判断和人工决定为准。
- PDF先读文字层；文字不足或大幅图片覆盖超过页面35%的页由 pypdfium2 4.30.0渲染后OCR。混合页保留文字层和补充OCR。读取 `pdfsrc`、实际链接和阅读器 `file` 参数，不把附件显示名称拼成下载URL。每份20 MiB、50页上限。这个检测不能证明任意混合版式都没有遗漏。
- 正常工作台每学院至多700个网页、40次API调用、200张图片和200份个人PDF，3个学院并行、每学院串行。达到限制保留待核项。2026-10-14初轮由当时的500页/35调用版本启动，各运行 `code/` 与 `input.json` 记录实际版本和预算。
- 复杂图片排版、跨域教师站、需点击的筛选/动态分页、多人同页身份归属仍可能失败；本批已用于调试，不属于未见验证集。保存页数或人数不能证明全院完整性。

## 夜间工作流准备

用户已选择先在工作台集中展示链接，服务器及外部推送之后配置。本轮未安装系统计划任务、未启用每日运行、未向任何渠道发送消息。

服务器提供 Python 3.12、锁定依赖、Chromium及 `DEEPSEEK_API_KEY` 环境变量。Windows使用本机Edge；Linux运行 `python -m playwright install --with-deps chromium`。本轮只在Windows实际验证，Linux尚未部署验收。

```bash
# 单批无交互执行；供未来服务器任务调度器调用。
python workbench.py --batch ntu-batch.json

# 内置每日定时模式（工作台进程需要持续运行；时间为Asia/Singapore）。
python workbench.py --nightly 01:00 --schedule-config ntu-batch.json
```

`--batch` 每次创建新批次，退出后可在同一个数据库的工作台查看。内置定时器按日期去重，停机期间不会补跑错过的时刻。部署认证、域名、TLS、进程守护与消息推送尚未配置。

## 批量复核与跨院汇总

人员和采集问题队列均支持逐项勾选、全选当前搜索/筛选结果和清空。切换筛选或标签会清空勾选，避免把隐藏条目带入决定。人员可批量排除或留待补查；采集问题可批量标为已处理或留待补查。提交前展示名单，须填写复核人、共同依据并确认；各条目的原来源自动附上。确认教师仍逐人核对字段。

`POST /api/jobs/<id>/bulk-decisions` 在一个事务内检查所有版本、写入逐条历史；任一冲突整批回滚。旧学院最终结论随条目变更重新待核。批量标为已处理只保存决定，不会自动补采。

批次导出由 `identity_export.py` 按同大学、同姓名及本人邮箱/同一主页/相同完整正文的额外证据合并；不同学院关联与完整原文分别保留，采集观察和人工决定不删除。同名本身不合并，出现在不同姓名下的共享邮箱不能用作合并证据。教师表仍为十列，多个学院、主页在同一行列出。不能判断新旧的职称/邮箱差异留空待核，候选值与来源保存在“合并说明 CSV”（`table=merges`）或批次 `format=json` 中；人员复核页点击“查看跨院关联”后读取并显示相关学院链接，不阻塞首次打开。职称排列次序变化不算冲突。

只有姓名的观察不阻断已有本人证据的个人页。`roster_identity.py` 将同一学院运行内、保存的正式师资名单中出现的姓名，关联到由官方名录明确链接的唯一本人主页：核对原名单正文、个人链接与来源资格，保存原件哈希和摘录，原条目转为“重复材料已关联”，名单来源加入导出证据。旧运行缺少来源资格字段时还须检查保存页面的标题；行政/联系人、旧名单、多个不同主页、缺少原件或已有人工决定时不自动关联。主记录仍有字段/读取问题时只保留主记录的待办。

邮箱字段可恢复有明确邮箱标签、被网页布局换行拆开的地址，原正文不变、不猜补域名；论文会议缩写里的 `@` 不单独视为坏邮箱。简介中的直接姓名/职称及紧随学位说明的院校职称可提供依据，当前任职与显式职称字段仍优先。名单关联、邮箱截断与职称漏填的保存页对照和验证见 [复核优化报告](../../runs/20261014-roster-profile/report.md)。

`material_delivery.py` 将材料读取状态与已确认字段的交付分开。保存的正式师资名录能明确关联姓名与个人链接时，主页访问失败、正文未读、附件访问失败可以单独登记，保留缺失原因和待补采事项，已确认字段继续出库。只存在姓名、来源用途不明或身份/字段归属有争议时不因此自动通过。正式名单个人行上的职称/邮箱可保留，不能用名单摘要冒充完整简介。前端可筛选“主页访问失败（可交付）”，采集问题中的 `deferred` 表示“已登记待补采”，不是读取成功；此状态不计入人工判断队列，但仍阻止把学院标为完整。

同学院的多份个人材料先以本人邮箱、具体履历共有片段等额外依据关联身份，再按保存页面明确标注的发布时间/更新时间选新版。网址日期、抓取日期、页脚年份和未来日期不参与排序；日期缺失、并列或同名身份无法关联时保留待核。明确是同一 CMS 文章的模板地址可关联为一人，失效别名不重复产生人员复核。所有原观察、原简介、旧页面和版本选择依据保留，不改写人工决定。

教师表仍为十列。教师行的主页单元格带标注批注；通过工作台“交付标注 CSV”或 `format=csv&table=notes` 下载完整说明，`table=statuses` 下载学院采集说明。记录的 JSON 保留 `delivery_notes`、`material_status`、`material_versions`。访问失败与日期择新维护证据见 [交付与材料版本报告](../../runs/20261014-delivery-versions/report.md)，当前 Excel 分表布局以上述交付格式为准。

“某某简介”等目录标题在未来采集时去除简介后缀；旧观察须有本人正文和页面标题共同支持才规范字段姓名，`name_normalization` 保留依据，原观察/ID不变。有行政或教辅岗位说明、而无教师职称或授课/导师依据的记录留待核实任职关系；明确兼有教学身份者不因此阻断。开发维护可用 `quality_pipeline.build(..., force=True)` 从当前代码重新生成派生质检快照，旧快照和人工决定保留。

人员多选支持“批量确认此人”：先预览每人的字段、简介和空值原因，统一填写复核人与依据，确认身份、学院归属和字段三项检查。保存仍逐人留审计记录并保持事务原子性；页面字段快照或人工修订版本已变化时拒绝过期提交。已经排除或关联为重复的条目须单独恢复，不在批量确认中直接重新入库。批量排除、留待补查和采集问题批量处理继续保留。

正式师资名单中的无链接姓名，在保存原件、师资来源资格和姓名位置均可核实时，可标为“仅名单信息（可交付）”；已知字段出库，主页和简介留空，注明本次材料未列出，不假称已检查整个官网。发现真实个人链接而未读取、同名身份不明、行政/学生/历史名单或缺少原件时仍待核。名单表格的职称行及 rowspan 可提供姓名单元格的职称依据。同一整份名单的重复副本通过内容哈希关联，不能仅凭同名合并不同名单。

特殊结构维护加入 `compatible_http.py`（仅特定 TLS 协商错误转用开启证书验证的 httpx）、`multi_profile_sections.py`（明确姓名标题与个人介绍边界的多人同页完整正文）、`faculty_navigation.py`（明确“团队教师”等子菜单中的同域姓名链接）。图片简历仍走原有 OCR 路径，不能把含未读图片的段落标成完整简介。职称规则降低无姓名排版碎片的优先级，统一“教授级高工”写法，对同一人的完整职称陈述保留非冲突的附加聘任；导师或跟随访问对象的职称不借给本人。

### 跨子站个人页、姓名与续采（2026-10-14）

正式师资名单明确链接的个人页，可跟进到同一大学的其他子域名（按 `xxx.edu.cn` / `xxx.edu` 边界核验），并保留原学院的名单归属。此权限不扩大为遍历其他学院的名单或新闻。个人页模板按域名分别缓存，图片和 PDF 只从该个人页自身站点读取并检查 robots；不同大学或未经名单关联的跨站入口仍单独记录。

姓名识别覆盖汉字扩展区，并保留拉丁字母姓名的空格、连字符、撇号与重音；明确的职称后缀另行剥离。姓名外形不是身份依据，仍须有正式名单或本人材料的对应关系。WebPlus 中独立于履历正文的姓名/职称/邮箱信息卡，在与名单姓名或正文开头对应时一并保存，避免只保存履历而漏掉联系方式。

页面上限约束每轮执行，已发现链接全部保存到 `targets.json` 和 `pending-targets.json`。前端“继续未采页面”创建新运行，复用旧原件和名单；每轮可设置页面及 API 调用上限。旧版丢弃的链接从已保存、已确认的目录和规则中恢复；旧姓名误判为文档的页面改排个人页补采。已读空页和失败页不会因续采自动反复请求。原件保持在各自运行中，证据未变化的人工决定沿用，变化的材料重新检查，学院完整性结论不继承。

## 复核排序与状态读取

“人员与异常”和“采集问题”左侧支持原始顺序、姓名升序、姓名降序和按复核原因排序。按原因时，同原因内按姓名排列；同名保持稳定次序，当前批量勾选和正在编辑的表单不因切换排序丢失。排序偏好保存在当前浏览器。

总览读取独立状态索引，并叠加最新人工决定、实时运行进度；索引仍核对材料与规则指纹。个人复核页默认只读取当前学院，跨院合并在导出时执行，或由复核人点击“查看跨院关联”按需查询。原件查看不再重复加载自动评估全文。维护重解析运行会保留上一轮原件与采集时间，不能当作一次新的官网采集；运行材料中的 reparse-provenance.json 记录其来源。

个人页结构识别由 `profile_layouts.py` 处理：要求独立信息卡姓名与正式名单中的目标人精确对应，再读取同组件的履历正文及重复章节，不扩大页面或跨站采集范围。已匹配结构无需额外模型推理。兼容的简称职称不覆盖正文中的详细聘任；本人卡片与本人简介有高依据的职称冲突时，职称单独留空并写“冲突”，已核实其他字段继续交付，采集问题保留待核事项。只有空模板标题的页面不冒充完整简介。验证材料见 [东南大学字段与复核体验维护报告](../../runs/20261015-seu-review-usability/report.md)。

## 图片师资表与个人菜单

`roster_tables.py` 在页面自己的标题或面包屑明确属于师资栏目时，先识别 HTML 表或纯图片正文，再交给普通名单规划。图片表须有姓名、性别、职称表头，并能按坐标对应同一行；不对齐、缺行、无表头或读取失败保留采集问题。每人保留原图、行号和字段依据，名单行不会作为完整简介导出。姓名或职称 OCR 分值低于 0.95 的行保留待核；此分值不是实际正确率，不能保证高分文字全部正确。复核页可直接对照指定行。

有多层组织分支的师资导航继续作为分支读取，不能仅凭短中文标签当作人名；明确师资标题下的单层姓名菜单或定义列表可提供个人入口。“学院研究生导师——姓名”“行业导师-姓名”等明确角色前缀支持规范姓名，原始标题仍保留。角色标注的个人介绍不能证明其中合著者、导师或研讨会纪念人物也是本院教师。

无重复姓名的个人正文，只有在页标题精确对应该人时，才从籍贯/性别开头的自述提取职称；“职称/职务”“职务/职称”视作明确字段标签。“曾任校聘…”不作为当前任职。保存材料中的分组名单与唯一个人页可按既有身份证据规则关联。验证范围与本轮遗留异常见 [新结构采集维护报告](../../runs/20261015-random-art-structures/report.md)。

作品图根据保存正文的明确“个人作品／代表作”等标题划定范围；图形标题要求 OCR 每行分值不低于 0.98。只有已有独立本人简介、图片没有明确简历或联系方式线索时，作品 OCR 才从交付简介中分离，原图、原始文字和识别记录仍保留。新简介或联系方式标题终止范围，纯图片简历不据此忽略。师资卡片简介里提到学生，不等于学生名单；有正式师资上下文、照片与独立姓名标签时可据原件关联唯一个人页。
