# 工作流执行约定

本记录对应 [Issue #16](https://github.com/normaltank/NewPlan/issues/16)，比较基线 `31797502b23c197bce77e9535467fc4b5bd5a01c`。现行执行入口为 [Matt 工作流](../../agents/workflow.md)，多工单任务按其条件进入 [多代理实施](../../agents/multi-agent.md)。

## 问题与修订

此前规则明确了技能入口和双维度审查，却没有写清多任务路线的派工、集成与完成证据。PR #1 的两个子代理实际负责审查，主代理负责验证和合并；这不能证明已执行多代理实施。该任务的最终状态查询中断后，完成答复也未及时给出。

本轮按 `ask-matt` 选为单一文档维护任务，以 `retro` 的环境改进视角和 `writing-for-agents` 修订：先记录选路，多任务默认按规格、工单和依赖实际派工；实施、合并、审查各自留证；收尾核对准确提交的 CI 并及时答复。任务记录与 PR 模板提供证据入口，未改全局技能正文。

## 验证与边界

所采用本地技能的摘要、文档链接与锚点、历史资料和非任务文件保真结果保存在 [validation.json](validation.json)。规范与需求两项审查、提交及 CI 状态记录在 Issue #16 和关联 PR；以对应提交为准。

本轮只验证文档配置，由主代理修改、两名独立子代理审查，没有假设已完成一次 `implement-spec` 端到端实施。当前证据是可读取的项目约定与审查记录；这些 Markdown 不是自动阻止跳步的程序。完整多代理实施仍需后续真实多工单任务的派工、集成和验收记录。本轮没有修改采集逻辑、正式数据、既有人工决定，也没有真实采集或付费调用。主工作区的并发修改保留。
