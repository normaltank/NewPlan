# 使用、人工复核与交付

启动入口见 [运维手册](operations.md)。网页上的“采集概览”用于提交与监视批次，“人工复核”按学院集中呈现异常及复核链接。业务判定和三表契约以 [CONTEXT](../CONTEXT.md) 为准。

## 提交学院

在“新建采集”入口粘贴表格，每行填写大学、学院名、学院链接，第四列可填师资列表链接。可从 Excel 复制，也可粘贴 CSV、制表符或 Markdown 表格。当前主工作台提供粘贴输入；不要把 Mission B 的文件上传能力当作此入口已有功能。

先预览、修正输入错误，再提交批次。预览不启动付费采集；提交后由采集工作进程处理。未提供名单入口时，完成后下载师资链接表，以便后续使用已发现的入口。

每个学院独立保留状态与结果。失败、预算耗尽或页面未覆盖时先查看原因与已保存材料，再决定补入口、补人员或重采；已有结果不必因个别页面失败全部作废。

## 人员与异常

默认优先处理待复核人员。填写复核人姓名，对照右侧字段、原文候选、来源和材料后确认教师、排除非教师或留待补查。姓名搜索、按姓名／原因排序可把同名和同类异常放在一起。

批量处理时先筛选，再勾选需要处理的条目。人员支持批量确认、排除和留待补查；采集问题支持批量标为已处理或留待补查。保存依赖当前记录版本，发生并发冲突时刷新并重新核对；不要用批量确认掩盖未查看的身份问题。

| 看到的情况 | 处理方式 |
| --- | --- |
| 官方名单有该教师，没有个人主页 | 可凭名单确认；缺失字段保留原因，无需仅因缺主页留待补查 |
| 主页实际无法访问 | 标为主页访问失败，可信信息仍可交付 |
| 个人主页与同院名单重复 | 有关联依据时自动合并；只剩姓名相同而身份无依据时再人工核对 |
| 教师照片被 OCR 提示 | 查看是否有需要采集的简历文字；少量误报可人工标已处理 |
| 同一人的材料有明确新旧日期 | 程序按可信日期选择并标注；同日冲突或身份不明时人工处理 |
| 候选含公共邮箱或旁人信息 | 核对归属后修正，不直接把页面出现的邮箱全部归给当前人 |

## 学院结论与下载

人员确认与学院完整性结论分别处理。只有名单入口、分支、分页和人员处理去向有覆盖依据时，才确认完整；无教师结论也需要依据。未完全核实的学院可以交付可信人员，同时保留“完整性未验证”。

总览的按大学下载会生成 ZIP，每所大学有自己的教师 Excel 和配套资料。教师 Excel 固定三个 Sheet，字段及分类见 [交付契约](../CONTEXT.md#教师交付表)。超长简介全文随大学包提供，CSV 也保留全文；单学院 Excel 遇到容量限制时可能提示改用完整交付包。

师资链接、来源标注和合并依据支持追溯。下载数量应与去重后的可交付记录核对；数目相等本身不证明学院名单无遗漏。重采后的材料和决定适用性由程序重新评估，必要时再核实改变的人员。
