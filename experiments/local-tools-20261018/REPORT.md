# 大批量采集：Jina 费用与三个本地候选的补测

**建议以本地采集和已有 Docling 为主，Jina 作为经验证的困难页面补采候选。Jina 的普通读取费用并不必然高，但没有证据支持让所有页面默认经过它。Scrapy、Scrapling、ScrapeGraphAI 之前没有完成实测，本轮已补做固定材料对照。**

本轮没有将候选接入正式工作台或现代 `MyPlan/server` 流程，没有整院重采，也没有新增付费订阅。

## Jina：按页面请求量计算

官方公开标准充值档为 **50 美元购买 10 亿 tokens**，折合每百万 tokens 0.05 美元。按上一轮完整 Markdown 的 27 次请求、168,102 tokens，样本均值为每次 6,226 tokens。

| 页面请求次数 | 按样本均值估算用量 | 按消耗量折算费用 |
|---:|---:|---:|
| 1 万 | 6,226 万 tokens | 3.11 美元 |
| 10 万 | 6.226 亿 tokens | 31.13 美元 |
| 100 万 | 62.26 亿 tokens | 311.30 美元 |

这些是普通读取的消耗量估算，不是实际充值账单。标准包以 50 美元购买；具体币种、税费和账户报价以充值页面为准。不含重试、额外 HTML 读取、可选 OCR 或下游 DeepSeek 调用。样本偏向诊断案例，不能当作所有学院页面长度的随机估计。教师数也不等于页面请求数，名单页、附件和再次更新均另计。

匿名免费接口公布的上限为每分钟 20 次；10 万次请求仅按此上限就至少需要约 83.3 小时，尚未计入其他等待。免费入口适合受限补采，不能依此保证服务器夜间大批量任务的时限。免费 API key 赠送套餐还标注了非商业用途，上一条回复仅提免费额度不够完整，生产预算不能建立在赠送额度长期可用的假设上。

来源：[Jina 公开价格](https://jina.ai/api-dashboard/pricing/)、[Reader 限速说明](https://jina.ai/reader/)；计算与限制见 `jina-cost-estimate.json`。

## 本地网页读取：三种方式都完成 26 页

版本：Scrapy **2.19.0**、Scrapling **0.5**。Scrapling 分静态 HTTP 与本地 Chromium 两种方式。使用固定 URL，不启动无限爬取或自动扩展学院范围。全部保留 HTML，并用同一套文本、链接和显式附件属性整理逻辑核对。

| 检查项 | Scrapy HTTP | Scrapling HTTP | Scrapling 浏览器 |
|---|---:|---:|---:|
| HTTP 200 页面 | 24/26 | 24/26 | 24/26 |
| 18 个已知个人页的姓名 | 16/18 | 16/18 | 16/18 |
| 13 个已核实邮箱证据点 | 12/13 | 12/13 | 12/13 |
| 六页硕导名单个人页链接 | 51/51 | 51/51 | 51/51 |
| 教授名单个人页链接 | 25/25 | 25/25 | 25/25 |
| 教授名单中全部姓名 | 34/34 | 34/34 | 34/34 |
| 既定三条论文证据 | 2/3 | 2/3 | 2/3 |
| 南通播放器中的 PDF 地址 | 1/1 | 1/1 | 1/1 |

两项未通过的个人页都是 HTTP 420：

- 邓小鹏：https://civil.seu.edu.cn/dxp/list.htm
- 张金霞：https://automation.seu.edu.cn/zjx/list.htm

本轮额外用 Jina 完整读取各重取一次，均返回 HTTP 200；邓小鹏的 `dxp@seu.edu.cn` 和张金霞的指定论文条目仍在返回正文中。因而 Jina 已展示了一个具体补采用途。不同出网环境、浏览器与提供方策略的影响尚未进一步拆分，不能宣称所有同类站点都能解决；提供方缓存和源站实时版本的等效性也没有独立证明。

本地三种方式在成功页面上保留了所有已指定证据点；没有展示 Scrapling 相对 Scrapy 在本组材料上的额外获取收益。所谓 24/26 是读取状态，不是最终教师准确率。这些结果也不证明当前正式浏览器流程一定会在两页上失败。

本轮未测试 Scrapy 的大规模排队、断点恢复，或 Scrapling 的结构变化后选择器恢复；网页存在这些工具并不意味着应更换现有队列。18 个分页链接出现项均保留，但没有进行名单自动翻页验收。

## ScrapeGraphAI：8 份冻结 HTML 的提取对照

版本 **2.3.1**，通过自带的模型接入方式调用我们已有的官方 `deepseek-flash`，不调用 ScrapeGraphAI 商业云 API。另设同一原始 HTML、同一任务要求和模型的直接调用对照。模型没有拿到评测期望姓名、邮箱或答案。

8 份材料包括 5 个个人页、2 个名单页和 1 个嵌入 PDF 栏目。个人页姓名 5/5、预先核实的个人邮箱 4/4 均正确；两张名单分别取得 34 人和 1 人，没有发现这两页多报姓名。以上仅覆盖这些检查项。

但存在四类不能直接交付的问题：

1. **简介不完整。** 王海兵页面的指定论文仍在 ScrapeGraphAI 的中间 Markdown 中，最终 biography 只有 535 字，遗漏该论文。直接模型对照也遗漏，说明仅增加这一层工具没有解决完整简介契约。其他成功字段不代表该简介完整。
2. **附件入口被预处理丢掉。** 南通护理与康复学院的 PDF 地址存在于原 HTML 的播放器属性中；转为 Markdown 后不再存在，ScrapeGraphAI 返回空附件列表。直接读取原始 HTML 的模型对照保留了 PDF 地址，本地显式属性提取也正确。不能据空结果判断学院无人。
3. **相对链接转换错误。** 刘杰原链接应为 `https://www.fynu.edu.cn/hxycl/info/1047/4102.htm`，模型输出漏了 `/hxycl`。两个模型对照均出现该问题，程序按网页基址解析的结果正确。链接解析宜继续由程序完成。
4. **导师资格混入职称。** 刘杰被填为“硕士生导师”；该名单没有提供其具体专业技术职称。需要现有字段规则核验，不能把结构化输出直接当作事实已确认。

用量：

| 对照 | 模型调用 | 输入 tokens | 输出 tokens | 合计 |
|---|---:|---:|---:|---:|
| ScrapeGraphAI | 8 | 46,106 | 7,664 | 53,770 |
| 原始 HTML 直接交给同一模型 | 8 | 147,446 | 7,918 | 155,364 |

ScrapeGraphAI 的转 Markdown 降低了相对“直接喂原始 HTML”的输入量，同时丢掉了特定附件属性。这不是与现有正式采集工作流的费用比较，也不证明这种预处理只有 ScrapeGraphAI 能做。以上仅测试这一模型、配置和材料，不排除更换配置或模型后的不同结果。

## 取舍

- **本地主力继续保留。** 页面原件能拿到时，先修正确的正文范围、链接解析和附件发现，避免给已解决页面增加外部请求。
- **Jina 值得做有边界的补采。** 当前已有两页正面证据；是否购买充值包，应由实际失败页数量、补回正确信息的比例和减少的人工量决定。总页数很大，并不自动意味着每页都要调用 Jina。
- **Docling 沿用本地路线。** 本轮没有重装或重测；图片、表格和文档优先在本地继续验证。
- **Scrapy / Scrapling 暂无替换主流程的依据。** 它们的价值还需结合确实存在的执行组织或页面获取问题验证。
- **ScrapeGraphAI 暂不纳入默认链路。** 本轮未证明其能解决我们已有的完整简介、附件发现和链接正确性问题；有用的模型字段提取也仍须程序核验。
