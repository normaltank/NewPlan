# Firecrawl、Jina Reader、Docling：第一轮隔离试验

**已完成小样本实测。Firecrawl 和 Jina 的完整读取模式值得进入下一轮网页采集对照；Docling 可作为图片和复杂表格的候选读取器。没有把任何一个工具整体替换进正式采集。**

本轮最有价值的发现是：输出模式、链接通道和表格导出方式，都会改变最终能取得的数据。默认正文模式不适合直接承担“尽可能拿全师资材料”的任务。

## 实际范围

- 网页：26 页，包括 18 个个人页、7 个名单页、1 个内嵌 PDF 栏目。个人页含过去的失败/成功样本，以及本轮新选的上海交通大学唐豪、谢应明页面。
- 两个网页提供方另外读取同一份三页 PDF，合计各 27 个 URL。Jina 调整输出模式后完整复测这 27 个 URL；另有 6 次 body 选择范围试验和 1 次 HTML 读取。
- Docling：4 份独立原件——多人 PDF、两张真实图片简历、一张背景有文字的教师照片；另加 PDF 第一页的扫描图对照，共 5 次转换。
- 原始 HTTP 同时读取网页，检查来源变化；这不是原系统的完整浏览器流程。既有 DS Fetch 输出只作历史参照，没有新增 DS 调用。

这些是指定材料的读取与解析试验，**没有重新验收整院入口发现、全部分页执行、身份去重或最终大学工作簿；全院完整性未验证**。2 个新个人页也不等于新学院验收。

## 网页结果

下表统计预先核对的具体证据点有没有保留，不能解释为全项目准确率。

| 检查项 | Firecrawl 全页输出 | Jina 自动正文 | Jina 完整 Markdown |
|---|---:|---:|---:|
| 18 个个人页的本人姓名 | 18/18 | 16/18 | 18/18 |
| 13 个已核实的本人邮箱 | 13/13 | 10/13 | 13/13 |
| 2 个新页面的明确职称 | 2/2 | 2/2 | 2/2 |
| 3 个曾被 DS Fetch 丢掉的论文条目 | 3/3 | 3/3 | 3/3 |
| 阜阳硕导六页的名单链接 | 51/51 | 51/51 | 51/51 |
| 阜阳教授页的个人页链接 | 25/25 | 25/25 | 25/25 |

教授页实际包含 34 个姓名，其中部分没有个人页链接。Firecrawl 的可读正文保留了 34 个姓名；Jina 有“张宏”“金凤”被多余粗体符号切开的现象，普通 Markdown 解析后只有 32 个连续姓名，但去除残留格式符号后 34 个都在。**这是可修复的格式问题，未把它计成实际丢失两位教师。** 两个提供方都保留了六页名单原件中的 18 个分页链接出现项；本轮按已知地址逐页读取，没有验证自动翻页循环。

### Jina 的关键配置

自动正文模式漏掉陈震、邓小鹏、唐豪的信息卡邮箱。尝试 `x-target-selector: body` 仍未取回；改用官方提供的 `x-respond-with: markdown`，三个邮箱全部恢复，随后对全部 27 个 URL 复测。该配置返回完整 Markdown，绕过自动正文筛选，代价是导航、页脚等噪声也更多。[官方格式说明](https://github.com/jina-ai/reader#using-request-headers)

这与我们的优先级一致：先把材料拿全，再清理。它仍不代表网页里的所有邮箱都属于页面主人，后续身份和字段归属核验必须继续。

### 南通特殊栏目不能只读“正文和链接列表”

护理与康复学院的栏目把 PDF 放在播放器中。两者普通正文/链接列表均未直接给出可用 PDF 链接：

- Firecrawl 的 `rawHtml` 中有渲染后的播放器地址，可以从 `file=` 参数恢复 PDF URL。
- Jina 另取 HTML 后，保留原页面的 `pdfsrc` 属性，可以恢复同一个 PDF URL。
- 已在试验读取器中验证两种明确嵌入地址的识别，没有将资源地址直接当作个人主页。

因此，“接口成功但没有教师正文”应先检查是否存在附件或嵌入播放器，不能直接判断学院无师资。

## PDF 和图片结果

参考材料为南通护理与康复学院三页名单。三页均已查看实际版面；姓名、职称和邮箱按 PDF 行独立对照。名单有 61 人、60 个完整邮箱，严海鸥一行在可见原件中只写到 `yho0704@163.`，继续保留为不完整。

| 方案 | 正确姓名对应 | 对应职称 | 按正确姓名绑定的完整邮箱 | 主要现象 |
|---|---:|---:|---:|---|
| Docling 原始单元格 + 试验续表读取 | 61/61 | 61/61 | 60/60 | 普通 DataFrame 导出会把续页首行当表头；原始单元格中仍完整 |
| Jina PDF 文本 + 试验行边界恢复 | 61/61 | 61/61 | 60/60 | 返回逐行文字，页交界可能连成一行，需要恢复边界 |
| Firecrawl PDF Markdown 表格 | 60/61 | 60/61 | 56/60 | 1 处姓名误字，3 处邮箱字符错误 |

Firecrawl 的具体反例：

| 原件 | 返回结果 |
|---|---|
| 张凤 | 张风 |
| 陈天喜：`tdfytianxi@163.com` | `tdfyttianxi@163.com` |
| 季建红：`jijianhong1234@126.com` | `jjianhong1234@126.com` |
| 崔志明：`czmspine@163.com` | `czmpine@163.com` |

Firecrawl 返回文本中存在 57/60 个正确完整邮箱；按正确姓名绑定后是 56/60，因为张凤的姓名被误写。这是一份 PDF 的结果，不能推广成 Firecrawl 对所有 PDF 都较差，但足以说明不能根据网页表现直接批准其附件输出。

Docling 的续表问题具体发生在周雪梅、倪钰飞两行。直接取三个 DataFrame 的数据行只有 59 人；读取原始单元格、区分真正栏目标题与续页首行后恢复 61 人。这个整理规则不依赖两人的名字，修复仅存在本试验中。

两张图片简历里，张红岩的“副教授”和鲍相志的“历史学博士、讲师”，以及各 5 个履历/研究片段均被 Docling 保留。本次选定图片未展示邮箱，没有补造。原有 OCR 在这两个姓名、职称上也已正确，因此不能宣称 Docling 在这两项上胜过原 OCR；其表格结构与位置证据更便于后续对账。合并单元格转成 Markdown 时可能重复文字，不能把字数变多解释为简介更完整。

将 PDF 第一页栅格化后，Docling 仍正确对应 24 个姓名、24 个职称、23 个完整邮箱。这是同一材料的扫描对照，不是额外独立学院样本，也不等于已经验证所有扫描质量。

背景有牌匾文字的照片仍被识别出了文字。Docling 是读取器，当前试验配置不会自动判断这些文字是否属于教师简介；照片用途和人员归属仍需现有业务规则处理。

## 隔离、版本和用量

- 独立目录：`experiments/tool-comparison-20261018/`。网页试验与 Docling 分别使用 `.venv-web`、`.venv-docling`；没有升级原工作台环境。
- Docling **2.140.0**，docling-core 2.102.0，RapidOCR 3.10.0，ONNX Runtime 1.31.0。完整依赖版本、模型文件哈希、代码哈希见 [版本记录](versions.json) 和两个 requirements lock 文件。
- 模型与缓存归本试验目录所有；实际模型文件约 733 MB。CPU 4 线程，5 次转换共约 110 秒，首次模型下载约 94 秒；没有调用远程模型 API。
- Firecrawl/Jina 为托管服务，**无法固定它们内部的服务端版本**。已保存调用时间、请求参数、完整响应及 Firecrawl 工具 Schema；本地隔离不等于托管服务可完全复现。
- [隔离核对](isolation-check.json)：检查的 306 个原代码/静态文件/依赖元数据均未改变，原 56 条人工决定的哈希未变，Git HEAD 未变。未启动或重启正式采集服务。
- 7 项针对实际反例的检查全部通过，见 [验证记录](test-results.txt)。测试覆盖试验读取逻辑，不替代业务验收。

调用记录见 [usage.json](usage.json)：

- **Firecrawl：31 次采集调用，额度从 927 降至 894，共 33 credits。** 留存了 27 个最终响应，响应元数据合计 29 credits。最初 4 次成功调用因试验输出子目录未创建而没有保存成功，已修正写入检查并重取；这 4 次计入用量，不计入质量比较。credits 不能直接当作美元。
- **Jina：61 次匿名请求**，覆盖默认、body、完整 Markdown、HTML 四种配置。返回用量计数合计 318,566 tokens；这是 Jina 的返回计量，不是 DS 模型消耗，未核对货币账单。
- **DeepSeek：0 次新增模型调用；Docling：5 次本地转换。**

## 下一步判断

保留两个网页候选：Jina 完整 Markdown + 必要时 HTML，及 Firecrawl 全页 Markdown/HTML/链接。图片和复杂表格优先继续验证 Docling；简单文字层 PDF 仍应与原读取方式比较，避免为已解决的材料增加不必要的开销。

接下来值得比较这两种网页候选与现有流程的整院结果，继续共用身份、来源和交付规则。当前结果尚不能证明任何组合对整院更完整、最终人工复核更少或长期运行更稳定；不发布替换，也不停止既有回归验证。
